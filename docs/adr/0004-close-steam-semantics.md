# 关闭 Steam 的语义：进程组终止与启动验证

用户触发含「关闭 Steam」步骤的操作时，旧实现只强杀 `steam.exe` 并轮询等它从进程表消失（预算 1s），随后立即 spawn——`steamwebhelper.exe` 等子进程在父进程被硬杀后残留为孤儿进程，新实例检测到旧残留自行退出，表现为「关闭后启动不起来」，且 spawn 成功即算成功、UI 报假成功。决定：关闭改为按「Steam 进程组」处理——exe 路径位于 Steam 目录下的进程（排除 `steamservice.exe`：它以服务形式高权限运行、普通权限杀不掉，且不阻塞 `steam.exe` 启动）全部终止，轮询等整组从进程表消失（预算 5s），超时中止并报错；启动后验证 `steam.exe` 存活（2s 窗口，失败重试 1 次），spawn 成功不算成功。

理由：进程组用路径过滤而非硬编码名单，Steam 未来新增进程自动覆盖（漏掉子进程正是本次 bug 根源）；等「整组消失」而非「steam.exe 消失」，因为孤儿进程不会自然退出，且顺带清理上次启动失败留下的残留；UI「Steam 正在运行」判定（只看 `steam.exe`，2s 轮询）与关闭判定（进程组）口径不同属有意为之——前者要快而便宜，后者要彻底。词条见 CONTEXT.md「Steam 进程组」「关闭完成」。

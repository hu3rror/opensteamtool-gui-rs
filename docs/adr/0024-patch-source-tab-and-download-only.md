# 补丁源落点：独立页签、中性措辞、草稿态与「应用即下载」

ADR-0023 把「源」做成一等概念，但把入口放进 Steam 页、列表内标「推荐」、应用与下载拆成两步。实际使用中三处都不成立：来源选择与 Steam 路径无关；「推荐」是替用户背书；应用后还要回首页再点一次下载才能验证源通不通。本 ADR 只改这三处，源模型、布局、构建号与部署路径不变。

## 决策

- **独立页签**：设置页签顺序为 General / 补丁源 / Steam / LuaConfig / About；补丁源卡片迁出 Steam 页，Steam 页保留路径、兼容性与只读的 `steam.cfg` 诊断行。新页签另有「检查补丁更新」，与主页面按钮触发同一动作。
- **中性措辞**：官方源写「官方源（长期未更新）」，两个社区分支写「社区维护」，界面不出现「推荐」。默认源与新配置、缺字段的老配置取同值（`PatchSource::default()`），不给官方源任何免费优势。
- **草稿态**：自定义源点选后进入草稿态——地址与布局两栏才出现，字段与下拉同宽；草稿不落盘、不校验，关闭对话框即丢弃，切页签保留。地址非法时原地报错，源不切换。
- **应用即下载**：草稿与已落盘源相同时按钮隐藏，不同时显示「应用并下载」。按下后持久化源并下载该源最新 zip，不部署；页签内给一行结果（成功「已下载 <源名>」，失败「下载失败：<错误首行>」）。已落盘布局与已部署布局不同时，加一行指向首页部署。部署仍是首页的动作。

## 理由

- 来源选择影响的是「下载从哪来」，与 Steam 路径无关；挂在 Steam 页制造「改路径会换源」的错觉。
- 措辞去掉「推荐」：本工具的立场是列出候选与状态，替用户选边会让失效信号失去意义。
- 「应用即下载」把「换了源能不能用」压缩成一次点击。只下载不部署，是因为换源后仍可能先看版本、比对文件；部署留给首页既有动作，避免一次点击动到 Steam 目录。
- 草稿态避免「下拉一换就重查」的半成品状态：换源是贵操作（网络 + 落盘），应显式确认。

## 被否的替代

- **保留在 Steam 页、只改措辞**：来源与路径混在一起的迷惑没解掉。
- **应用即部署**：多认识一个会自动动 Steam 目录的按钮，风险高于收益。
- **自定义源一选就落盘**：非法地址会先污染配置再报错。
- **默认源保持官方**：官方源长期无新 release，默认它等于让首次使用必然遇到「不工作」。

## 未验证

- 官方源长期未更新是研究文档 `docs/research-patch-dll-sources.md` 的结论（截至该文档采样日），非长期保证；措辞取「长期未更新」而不是「已停更」正是为此。
- 「应用即下载」后的失败文案只取错误首行，对多行网络错误可能损失细节；是否够用于真实失败模式未验证。

## 验收

设置页签顺序与卡片位置符合上文；两语言列表无「推荐」字样；新装与缺字段老配置同源；换源自定义源需一次显式「应用并下载」；页签内结果行成功与失败各出现一次；部署仍在首页。

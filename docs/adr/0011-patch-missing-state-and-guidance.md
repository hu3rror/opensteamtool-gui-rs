# 未下载补丁的状态语义与操作区引导

便携包默认不携带目标 DLL（`tools/build-release.ps1` 只放 `dlls/` 占位 README，补丁需「检查更新 + 下载并解压」拉取），因此「未下载」是全新安装的默认状态。此状态下有两处 UX 缺陷：

1. 未部署分支的「应用补丁并启动」照常可点，点下去才报 `Precheck::NoTargetDlls`（「dlls/ 目录缺少目标 DLL 文件」）。
2. 「下载并解压新版本」按钮只在检查更新成功后出现（`update_flow::derived` 的 `download` 字段），全新状态下根本没有下载按钮可点——「引导下载」若无配套可达性就是死引导。
3. 已应用且 Steam 未运行时，启动按钮写「正常启动 Steam」——补丁已在 Steam 目录，一点启动即带补丁加载，并非「正常启动」。

## 决策

- **判据文件本位**：「补丁已下载」以 `dlls/` 三个目标 DLL 文件齐全与否为准（新增 `dll::dlls_present()`，与部署前置校验同谓词）；`version.txt` 记录不作数。本地版本行、更新对比（`derived` 的入参）、按钮置灰三处共用同一判据。由此消除边角死路：有版本记录但文件被删时，此前会显示 "vX" 且对比误判「已是最新」→ 下载按钮不出现；现按「本地缺失」处理，检查后下载入口必然出现。
- **置灰范围收窄**：仅「应用补丁并启动」在「未部署 + 缺文件」时置灰（原先行报错改为前置不可点）。「正常启动 Steam」不依赖 `dlls/`，保持可点；已应用分支的卸载/重启/退出类动作均不依赖 `dlls/`，不受影响。
- **引导两步走，不自动联网**：操作区下方一行弱化提示「请先点击『检查更新』，再『下载并解压新版本』」。否决「启动时自动检查更新」方案：每次启动多一次 GitHub API 调用，且检查结果流转本就走 `update_flow` 单一事实源，手动触发零代码路径变更、零网络行为变化，成本最低。
- **已应用启动按钮弃用「正常」**：文案改为「▶ 启动 Steam」（新增 i18n 字段 `btn_launch`）。「正常启动」仅保留给未部署时的启动（那里才是真·正常）；`btn_launch_normal` 字段名与文案不动。词表与注释同步：`CONTEXT.md` 的「操作/重启/托盘」词条、「workflow.rs` `Action::Launch` 注释、托盘与 `ui.rs` 的「等价『正常启动』」均改为「直接启动」口径；`ADR-0010` Neutral 示例列表补「启动」。

## 否决的方案

- 缺文件时直接渲染「下载最新补丁」按钮并绕过检查流程：改动 `update_flow` 契约，破坏「检查结果唯一事实源」架构，收益仅是省一次点击。
- 启动自动检查更新：见上，引入启动期网络依赖。

验收：`cargo check --workspace --all-targets` / `cargo clippy --workspace --all-targets` / `cargo test --workspace` 全绿；手动核对——全新便携包运行：应用按钮灰 + 引导行，点「检查更新」成功后「下载并解压新版本」出现；已应用且 Steam 未运行：按钮显示「启动 Steam」；本地版本行在缺文件时恒显「未下载」。

# 补丁版本号退出 UI：本地/线上版本降级为内部资源

主页面精简（#32）后，补丁的本地/线上版本号不再渲染于任何界面（#30 起补丁检查
结果文案即已不含版本号）。决定：「本地版本 / 线上版本」是内部概念（GLOSSARY.md
词条，永不渲染），版本比较只在「更新流程」内部完成；界面可见的版本信息只剩
「软件版本」与「应用更新检查」（App 自身版本）。

## 为什么版本号离开 UI

- **版本混淆风险**：界面同时出现两类版本号——本工具的「软件版本」与补丁的
  「本地/线上版本」——用户极易把补丁行上的 "vX.Y.Z" 读作本工具版本（反之亦然），
  误报/误诊层出不穷；对多数用户唯一有意义的版本信号是「App 是否有新版本」。
- **上游适配节奏与版本脱钩**：补丁（OpenSteamTool）的版本更新滞后于 Steam 更新，
  真正说明「当前 Steam 版本能不能用补丁」的是兼容性体检（健康度），不是补丁版本
  号；补丁版本号对用户不构成可用性信息，留着只会引导错误解读。
- **版本比较无用户操作价值**：下载可用性由「本地版本 == 线上版本」派生，结论用
  「补丁已是最新 / 发现新补丁」等文案表达即可，数字本身没有消费方。

## 决策

- 主页面不渲染任何补丁版本行（#32）；补丁检查结果文案统一走 `render_patch_notice`，
  无版本数字（#30 口径，ADR-0011 修订）。
- `update_flow::UpdateLine` 行分类删除；`UpdateNotice` 不携带版本号。
- 「软件版本」（crate 版本，构建固化）与「应用更新检查」是唯一的用户可见版本面：
  数值比较在模块内完成（`is_newer_version`），UI 只展示「发现新版本 vX / 已是最新」。
- 内部仍严格区分「本地版本」（`dlls/version.txt`）与「线上版本」（GitHub tag）：
  比较语义、文件本位判据（ADR-0011）不变，只是不渲染。

## 否决的方案

- 主页面保留「补丁版本」小字行（信息完整性）：与「版本混淆风险」直接冲突，且
  #32 主页面精简本身就是去信息噪音；版本行没有可操作消费方。
- 把补丁版本号并入「关于」区展示：依旧无法消解两类版本并存的混淆，且把内部资源
  当作公开信息是错误定位——补丁是随下载更新的资源，不是软件事实。

## 验收

主页面与设置对话框均不渲染任何补丁版本号（「软件版本 / 应用更新检查」的 App 版本号不受限）；补丁检查结果文案（双语）不含数字；
`cargo test --workspace` / `cargo check --workspace --all-targets` / `cargo clippy
--workspace --all-targets` / `cargo fmt --all --check` 全绿。
